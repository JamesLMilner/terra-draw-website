# Testing

> Thirty-nine Playwright tests exercise the production build end to end — per-screen smoke checks, UI-driven drawing and measurements, undo/redo/clear, both export formats, automatic light/dark theming (including dark-toolbar contrast), committed documentation captures for the home, demo and API docs screens, a twelve-capture home responsivity matrix and fixture meta-tests — and any console error fails the test that produced it.

## Overview

- **Playwright, Chromium only.** A single project runs Desktop Chrome ([`playwright.config.ts:23-28`](../playwright.config.ts)); there is no unit-test runner in the stack (see [Architecture](2.architecture.md)).
- **The production build, not the dev server.** The `webServer` block runs `npm run build` before `vite preview` ([`playwright.config.ts:17-22`](../playwright.config.ts)), so tests check the real bundled output that ships to GitHub Pages.
- **Nine specs share three auto-applied fixtures.** Every spec imports the extended `test`/`expect` from [`tests/e2e/fixtures.ts`](../tests/e2e/fixtures.ts), which fails tests on console errors, isolates `localStorage` and tracks finished map tiles (see below).
- **Thirty-nine tests, one an intentional expected failure.** The six meta-tests in [`fixture-self-test.spec.ts`](../tests/e2e/fixture-self-test.spec.ts) prove the fixtures and the capture guards work; the console-error one is marked with `test.fail()`, so the suite still exits 0. Once the browser is installed, the capture specs and the theme-swap tests dominate the runtime (excluding the one-off build).

## Fixtures and Policy

[`fixtures.ts`](../tests/e2e/fixtures.ts) extends Playwright's `test` with three fixtures, all `{ auto: true }` so they apply to every test without being requested:

- **`failOnConsoleError`** ([`fixtures.ts:59-85`](../tests/e2e/fixtures.ts)) collects every `console` message of type `error` and every uncaught `pageerror`, then fails the test during teardown with a message that includes the current page URL and each collected message. Console `warning`s are logged to the test output but never fail a test.
- **`cleanStorage`** ([`fixtures.ts:24-38`](../tests/e2e/fixtures.ts)) runs `context.addInitScript` to remove the app's `localStorage` keys — `terra-draw` (feature snapshot) and `tab` (active side-panel tab) — before app scripts run on every navigation. Each test therefore starts from the default state: Info tab, no features.
- **`mapTileTracker`** ([`fixtures.ts:40-56`](../tests/e2e/fixtures.ts)) records every finished OpenFreeMap map-tile request per page from before navigation, matching the vector `/planet/<version>/{z}/{x}/{y}.pbf` (version segment optional) and raster `/natural_earth/<layer>/{z}/{x}/{y}.png` shapes; glyph, sprite and style requests are excluded. It listens on `requestfinished` rather than `response` so the tile body is fully downloaded; [`getMapTileUrls(page)`](../tests/e2e/fixtures.ts) ([`fixtures.ts:113-115`](../tests/e2e/fixtures.ts)) exposes the live list.

Because all three fixtures are auto-applied, specs must import `test`/`expect` from `./fixtures`, not `@playwright/test`.

[`fixtures.ts`](../tests/e2e/fixtures.ts) also exports `captureScreenshot(page, path)` ([`fixtures.ts:894-948`](../tests/e2e/fixtures.ts)), which gates on map rendering and validates the captured bytes before writing. Chromium can transiently reject `Page.captureScreenshot` while several headless browsers render WebGL maps; those protocol errors are retried with linear backoff (400 ms, then 800 ms — three attempts in all). Independently, Chromium can return a *successful* screenshot with blank or *partially composited* map pixels (a compositor/readback race, seen as `GPU stall due to ReadPixels` warnings, and once as a half-uniform capture). Each attempt therefore decodes its own JPEG buffer and counts exact colours in the map region ([`fixtures.ts:509-591`](../tests/e2e/fixtures.ts)) using the live overlay bounding boxes as a mask: only unmasked pixels inside the `.maplibregl-canvas` rect count, so toolbar, control and attribution pixels never contribute, whatever sits on top (including the toolbar wrapped over the map below 900 px). A blank map scores 1 colour against the more than 32 required ([`fixtures.ts:454`](../tests/e2e/fixtures.ts)); painted maps score in the hundreds or more. A capture that passes the colour check is then cross-checked cell by cell against a fresh capture of the live canvas ([`fixtures.ts:622-867`](../tests/e2e/fixtures.ts)): the canvas capture gets the same overlay mask before its own blank-canvas guard, an 8×8 grid skips cells under overlays, and a capture cell that is a single flat colour while the canvas at the same place is varied marks the capture as uncomposited. Up to two stray cells are tolerated, so a defect spanning a compositor tile is caught while a legitimate flat region or antialiased edge is not. A failing result re-runs `waitForMapTilesReady` — the idle gate forces a fresh MapLibre frame itself — then waits the backoff before retrying ([`fixtures.ts:902-907`](../tests/e2e/fixtures.ts)). The file is written only after validation, so a failed, blank or partial capture never reaches disk; if every attempt fails the helper throws with the path and the colour count (`Refusing to write a blank screenshot…`). All five capture specs — [`documentation/home.spec.ts`](../tests/e2e/documentation/home.spec.ts), [`documentation/api-docs.spec.ts`](../tests/e2e/documentation/api-docs.spec.ts), [`documentation/demo.spec.ts`](../tests/e2e/documentation/demo.spec.ts), [`responsivity/home.spec.ts`](../tests/e2e/responsivity/home.spec.ts) and [`dark-mode.spec.ts`](../tests/e2e/dark-mode.spec.ts) — use it, so every current and future capture is gated.

The module also exports the helpers the theming tests build on: `relativeLuminance(page, selector, property)` ([`fixtures.ts:127-175`](../tests/e2e/fixtures.ts)), which throws rather than returning a misleading value for a missing or fully transparent element; `expectDarkChrome(page)` ([`fixtures.ts:183-200`](../tests/e2e/fixtures.ts)), the shared dark-surface/light-text assertion; and `mapCanvasLuminance(page)` ([`fixtures.ts:326-349`](../tests/e2e/fixtures.ts)), which masks out every live DOM overlay bounding box so it samples basemap pixels only, and returns only once two consecutive captures agree to within a 0.002 mean-luminance delta (6 s bound) so a label or line fade in progress is never sampled. `mapCanvasLuminance` is used as a paint-readiness gate before dark captures and theme swaps, not as a palette assertion.

### Readiness Without Sleeps

Tests never use `page.waitForTimeout` or wait for `networkidle`. The readiness signal is the `#select` toolbar button: `MapButtons` is only rendered once Terra Draw exists ([`home/index.tsx:151-153`](../src/routes/home/index.tsx)), and Terra Draw is only constructed after MapLibre's `style.load` fires ([`home/index.tsx:53-55,62-65`](../src/routes/home/index.tsx)). Waiting for `#select` therefore proves the real map pipeline ran — UI readiness only, not that tiles were fetched or painted. Screenshot captures use a separate render gate (below).

> [!NOTE]
> Several console warnings appear routinely on healthy runs and are non-fatal: Chromium/ANGLE's `GPU stall due to ReadPixels` (map rendering), `Setting overlaysContent is only supported from the top level browsing context` (the cross-origin TypeDoc iframe) and MapLibre's asynchronous `Image "…" could not be loaded` on the first marker draw — the last is pre-existing and reproduces in light mode with no style swap. The demo spec adds around 16 MapLibre `Max vertices per segment is 65535: bucket requested ...` warnings while rendering the 69,577-coordinate line; the line still renders fully because MapLibre splits segments. The fixture fails on `error` and `pageerror` only.

### Screenshot Gating — `waitForMapTilesReady`

Every capture through `captureScreenshot` first awaits [`waitForMapTilesReady(page)`](../tests/e2e/fixtures.ts) ([`fixtures.ts:373-444`](../tests/e2e/fixtures.ts)), a hard gate that refuses to capture until MapLibre itself reports the map has finished rendering:

1. **Non-map screens return immediately.** The gate checks for `#maplibre-map`; the `/#/api/` TypeDoc route has none, so it is a no-op there.
2. **The map handle.** It waits for `window.__terraMap`, the MapLibre instance exposed unconditionally by [`setup-maplibre.ts:99-101`](../src/routes/home/setup-maplibre.ts) and declared on `Window` in [`declaration.d.ts:30-35`](../src/declaration.d.ts). The hook ships in production builds because Playwright runs against `npm run build && vite preview`; if it never appears the gate throws with the page URL and `window.__terraMap was never exposed. Refusing to capture a potentially blank map.`
3. **A fresh `idle`.** It attaches `map.once("idle")` and only then calls `map.triggerRepaint()`, so the `idle` that follows is necessarily one this call initiated — a plain listener could hang on an already-settled map. An in-page timeout rejects if no `idle` arrives; the hook wait and the idle wait share one 30 s deadline.
4. **Compositor settle.** A final double `requestAnimationFrame` lets the compositor catch up before the screenshot.

Both stages fail loudly — never silently — with the page URL (`… Refusing to capture a potentially blank map.` for a missing hook, `… Refusing to capture a blank map.` for an `idle` timeout). Gating on MapLibre's own event replaces the old tile-count and quantised-colour polls, which shared a false-pass mode: the colour poll read a `.maplibregl-canvas` element screenshot — a crop of the composited page including every DOM overlay above it — so toolbar, button and attribution pixels satisfied its threshold before MapLibre had painted a single tile. That race produced the silent blank captures (cold first paint under parallel load at the first test of each colour-scheme block); MapLibre's `idle` cannot be satisfied by overlays.

A blocked `tiles.openfreemap.org` still fails the run — the console-error fixture flags MapLibre's tile-load errors — and any capture that comes back flat is rejected by the byte validators below, so the suite never commits a blank asset.

This gate proves MapLibre finished rendering, which is necessary but not sufficient: a later full-viewport capture can still read back blank pixels, so `captureScreenshot` additionally validates the captured bytes and retries a blank result (see above). That guard has three meta-tests ([`fixture-self-test.spec.ts:44-76,90-151,166-258`](../tests/e2e/fixture-self-test.spec.ts)): one stubs `page.screenshot` with a 1×1 blank JPEG, one with a half-uniform capture, and one with a flat map covered by the real live overlays — the exact false pass the old gate allowed — and all assert the loud rejection plus nothing reaching disk.

### Smoke — `smoke.spec.ts`

**Home screen (`/#/`)** ([`smoke.spec.ts:3-30`](../tests/e2e/smoke.spec.ts)): title matches `/Terra Draw/i`; the `Home`, `API Docs` and `Sponsor` links are visible; the Info and GeoJSON tabs and the `Collapse side panel` button are visible. **API docs screen (`/#/api/`)** ([`smoke.spec.ts:32-44`](../tests/e2e/smoke.spec.ts)): exactly one visible `iframe`, with `src` equal to `https://jameslmilner.github.io/terra-draw/modules.html`. The content is cross-origin and is not asserted.

### Automatic theming — `dark-mode.spec.ts`

The spec proves the theme contract through public interfaces only — computed styles, network requests and canvas pixels — using Playwright's per-test colour scheme rather than app internals.

- **Light guards** ([`dark-mode.spec.ts:253-273`](../tests/e2e/dark-mode.spec.ts)): with `colorScheme: "light"`, body and header backgrounds and body text must equal the exact shipped values (`rgb(250, 250, 250)`, `rgb(253, 253, 253)`, `rgb(68, 68, 68)`), and the logo and GitHub marks must have no CSS filter. This is the regression guard for the light-identical guarantee.
- **Dark invariants** ([`dark-mode.spec.ts:276-388`](../tests/e2e/dark-mode.spec.ts)): with `colorScheme: "dark"`, both routes must compute to dark surfaces and light text (WCAG relative-luminance thresholds, deliberately loose so palette tweaks do not break the suite), header marks must be inverted, and the first load must request the dark OpenFreeMap style. The API docs route's dark evidence stays uncommitted in `.opencode/tmp/dark-mode/api-docs-dark.jpg` — a gitignored temporary path — and is attached as `dark-api-docs` ([`dark-mode.spec.ts:372-387`](../tests/e2e/dark-mode.spec.ts)); the committed dark home capture now lives in [`documentation/home.spec.ts`](../tests/e2e/documentation/home.spec.ts).
- **Toolbar contrast regression** ([`dark-mode.spec.ts:314-371`](../tests/e2e/dark-mode.spec.ts)): the map-overlay toolbar must stay distinguishable above the OpenFreeMap dark style's near-black background (`#0c0c0c`). The strongest of the `#select` button's surface/border edges must reach 3:1 contrast, the weaker of the two 1.5:1, and the label 4.5:1 against its own surface; the surrounding panel border must also reach 1.5:1. The test first proves the basemap below the toolbar actually painted dark by sampling the live canvas band. The dedicated `--color-map-control-*` tokens behind this are described in [Architecture](2.architecture.md#theming).
- **Live switching** ([`dark-mode.spec.ts:391-521`](../tests/e2e/dark-mode.spec.ts)): starting light, `page.emulateMedia` flips to dark and back, asserting `styles/positron` → `styles/dark` → `styles/positron` style requests and canvas luminance in each state. The second test draws a polygon, a point and a marker *after* the swap and asserts all three persist through the reverse swap, covering the image-dependent `td-point-marker` layer.

### Fixture self-tests — `fixture-self-test.spec.ts`

- Logs a deliberate `console.error` and marks the test `test.fail()`, proving `failOnConsoleError` fails tests that emit errors while the suite still exits 0 ([`fixture-self-test.spec.ts:23-34`](../tests/e2e/fixture-self-test.spec.ts)).
- Stubs `page.screenshot` with a 1×1 blank JPEG and asserts `captureScreenshot` rejects with `Refusing to write a blank screenshot` and leaves no file on disk ([`fixture-self-test.spec.ts:44-76`](../tests/e2e/fixture-self-test.spec.ts)). The stub makes the readback race deterministic instead of probabilistic.
- Stubs `page.screenshot` with a half-uniform capture — the left half of the map band flattened to `#2b2b2b` while the right half stays painted — and asserts the canvas cross-check rejects it and nothing reaches disk ([`fixture-self-test.spec.ts:90-151`](../tests/e2e/fixture-self-test.spec.ts)). This is the exact defect observed once as `home-medium-dark-portrait.jpg`.
- Builds the shape of the diagnosed false pass — a viewport-sized JPEG filled flat with `#2b2b2b`, with the real toolbar and control elements pasted back at their live rects — and asserts the canvas cross-check rejects it and nothing reaches disk ([`fixture-self-test.spec.ts:166-258`](../tests/e2e/fixture-self-test.spec.ts)). The overlay-masked colour check passes on JPEG ringing (~50 colours, just above the 32 threshold), so only the canvas cross-check catches the flat map; the previously observed blank artifact scored 24 and failed the colour check outright.
- Writes both app keys, reloads and asserts `localStorage` is clean, proving the isolation script runs before app scripts ([`fixture-self-test.spec.ts:264-281`](../tests/e2e/fixture-self-test.spec.ts)).
- Injects a large bright overlay over the dark map and asserts `mapCanvasLuminance` is unmoved, proving it samples basemap pixels only ([`fixture-self-test.spec.ts:291-347`](../tests/e2e/fixture-self-test.spec.ts)).

### Demo captures — `documentation/demo.spec.ts`

[`documentation/demo.spec.ts`](../tests/e2e/documentation/demo.spec.ts) regenerates the two committed demo captures — [`screenshots/docs/demo-light.jpg`](../screenshots/docs/demo-light.jpg) and [`screenshots/docs/demo-dark.jpg`](../screenshots/docs/demo-dark.jpg), both 1440×900 — from a single Terra Draw-native LineString on every suite run, attaching them to the report as `demo-light` and `demo-dark`. It runs under a 120 s timeout with `reducedMotion: "reduce"`.

- **Seeding.** A later-registered `context.addInitScript` writes `collection.features` straight into the app's `terra-draw` `localStorage` key after the `cleanStorage` fixture's script, so the seed survives every navigation. The restore path is asserted for real: Total `1`, Lines `1`, Points `0`, Polygons `0`, and one table row.
- **Fixture provenance.** [`tests/data/big-route.geojson`](../tests/data/big-route.geojson) is a Terra Draw-native FeatureCollection — one 2D `LineString` with 69,577 coordinates and `properties.mode: "linestring"` (1.58 MB, compact). It was derived once from a previous route export: all 19 line features (14 `MultiLineString`s → 40 parts, plus 5 `LineString`s) merged in order, altitude stripped, the 257 photo `Point`s and all other properties dropped, with no rounding or decimation and no consecutive duplicates. The original multi-feature export was untracked and is not in the repo.
- **Export before selection.** The GeoJSON textarea is parsed before any row click and asserted exactly: one feature, `LineString`, 69,577 coordinates, a 2D first coordinate and `properties.mode === "linestring"`. Selection is deliberately avoided — see the dense-feature caveat under [Caveats](#caveats).
- **Deterministic framing.** Mocked geolocation plus reduced motion makes the `#geolocation` click an instant, exact centre + zoom 14 jump; eight `-` keypresses step out to zoom 6, and one isolated wheel event trims to zoom 5.7998 (tile zoom 5). Framing is pixel-identical across consecutive regenerations.
- **Shared tracker and overwrite safety.** The spec reads the shared [`getMapTileUrls(page)`](../tests/e2e/fixtures.ts) tracker instead of attaching its own listener. On top of the generic render gate that `captureScreenshot` applies, it waits for at least three finished tiles at the final camera's zoom (`/planet/(?:[^/]+/)?5/...`) before returning to the Info tab and letting the light capture overwrite the committed image.
- **Dark capture mid-scene.** After the light capture, `page.emulateMedia({ colorScheme: "dark" })` fires the app's `matchMedia` listener, swapping the basemap live to the OpenFreeMap dark style while the `transformStyle` carry-over preserves the seeded route layer. The test gates on `mapCanvasLuminance(page)` dropping below `0.2` — a style request alone would not prove the dark basemap had painted — then captures `demo-dark.jpg` through the same guard and attaches it as `demo-dark`.

Regenerate just the demo captures with `npx playwright test tests/e2e/documentation/demo.spec.ts`; a full `npm test` also rewrites them.

## Running the Tests

Playwright's browser is a separate download. Install it once per machine, then run the suite ([Getting started](1.start.md) covers the broader setup):

```bash
npx playwright install --with-deps chromium
npm test
```

`npm test` runs `playwright test --config=playwright.config.ts` ([`package.json:10`](../package.json)). Before the first test, Playwright starts:

```
npm run build && npx vite preview --host 127.0.0.1 --port 4173 --strictPort
```

and waits for `http://127.0.0.1:4173` with a 120-second budget. Locally an existing server on port 4173 is reused (`reuseExistingServer: !process.env.CI`); in CI a fresh one is always started.

> [!WARNING]
> `npm test` starts with `npm run build`, so it wipes and rewrites `docs/` — the Vite build output ([Deployment](6.deployment.md)), which is gitignored. Never treat `docs/` as documentation.

> [!NOTE]
> `reuseExistingServer` means a stale preview left on port 4173 will be reused as-is. If local results look wrong, stop any running preview before retrying.

Screenshots are written by the documentation, responsivity and dark-mode specs — each capture render-gated and buffer-validated first (see [Fixtures and Policy](#fixtures-and-policy)) — and attached to the test report. The root [`screenshots/`](../screenshots/) directory holds two committed area directories, so changes appear in Git diffs for review and the images can be embedded in documentation. All committed captures are JPEG (quality 85):

- [`screenshots/docs/`](../screenshots/docs/) — five assets: the light and dark home captures (`home-light.jpg`, `home-dark.jpg`), the light and dark demo captures (`demo-light.jpg`, `demo-dark.jpg`) and `api-docs.jpg` (the light view; the themed page chrome leaves the image unchanged).
- [`screenshots/responsivity/`](../screenshots/responsivity/) — twelve assets, one per size × scheme × orientation (`home-small-light-portrait.jpg` and so on).

Unlike these, the generated `test-results/` and `playwright-report/` directories are gitignored. The only dark evidence left uncommitted is the API docs capture in the gitignored `.opencode/tmp/dark-mode/`. The default local `list` reporter does not display attachments — rerun with `npx playwright test --reporter=html` and open the report with `npx playwright show-report` to view them.

## CI

The `build` job in [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on Ubuntu 24.04 with Node `24.18.0` ([`ci.yml:20`](../.github/workflows/ci.yml)):

1. `npm ci` ([`ci.yml:60-61`](../.github/workflows/ci.yml)).
2. `npx playwright install --with-deps chromium` ([`ci.yml:62-63`](../.github/workflows/ci.yml)).
3. `npm run build` ([`ci.yml:64-65`](../.github/workflows/ci.yml)).
4. `npm test` ([`ci.yml:66-67`](../.github/workflows/ci.yml)) — now the full suite, though the step is still labelled `Production Build Smoke Test`.

The separate `lint`, `package-lock` and `typecheck` jobs cover style and types. The deploy workflow only builds the site — testing is CI's responsibility ([Deployment](6.deployment.md)).

## Debugging

Playwright's CLI adds three useful modes (see [Playwright's debugging guide](https://playwright.dev/docs/debug)):

- `npx playwright test --headed` — watch the browser while tests run.
- `npx playwright test --debug` — headed with the Playwright Inspector (`PWDEBUG=1`); add `--timeout=0` to remove timeouts while stepping.
- `await page.pause()` in a spec — pauses at that line with the browser open; requires headed mode.

When working on map interactions, remember that readiness is gated on `#select`, vertices are clicks inside `#maplibre-map`, and this Terra Draw version has no double-click-to-finish: `Enter` finishes polygon/line shapes and `Escape` cancels them.

Traces from `trace: "on-first-retry"` land in `test-results/`, alongside reports in `playwright-report/`; both are gitignored ([`.gitignore:6-7`](../.gitignore)). The checked-in screenshots live separately in [`screenshots/docs/`](../screenshots/docs/) and [`screenshots/responsivity/`](../screenshots/responsivity/).

## Caveats

- **Specs are not type-checked.** `npm run typecheck` covers `src/**/*` only, so `playwright.config.ts` and the specs — which reference `process` without `@types/node` — are outside the program (see [Architecture](2.architecture.md), tech-debt item 10).
- **External runtime dependencies.** Map readiness depends on MapLibre's `style.load`, which needs the keyless OpenFreeMap style endpoint ([`setup-maplibre.ts:65-66`](../src/routes/home/setup-maplibre.ts)), and the map-screen tests need egress to `tiles.openfreemap.org` for the styles, tile bodies, glyphs and sprites. A blocked endpoint fails runs rather than merely slowing them, and the screenshot gates fail loudly rather than committing a blank asset. The API iframe is cross-origin, so its content is never asserted, and it emits the `overlaysContent` warning noted above.
- **Colour heuristic assumes a painted map.** The captured-bytes colour check expects more than 32 exact colours on unmasked canvas pixels; a uniform view (for example mid-ocean with no labels) could theoretically trip it, and `waitForMapTilesReady` now accepts only a `timeout` override. The gate itself samples no pixels — it waits on MapLibre's `idle`, which fires for a uniform basemap too. The captured-bytes guard has a matching assumption: it rejects a flat capture cell only when the live canvas at the same place is strongly varied, so a legitimately flat region is never flagged.
- **Area units vary with zoom.** `InfoTab` switches polygon area from `Area (m2)` to `Area (km2)` at 1,000,000 m² ([`InfoTab.tsx:8,62-74`](../src/components/info-tab/InfoTab.tsx)). At the default zoom a screen-visible polygon is always ≥ 1 km², so the drawing spec accepts either unit rather than pinning one.
- **Dense features stall selection.** Clicking the table row for the demo's 69,577-coordinate line never completes within the 120 s timeout: Terra Draw's select mode creates around two guidance features per coordinate (≈139k). Both demo captures are therefore taken unselected, with no `Selected Feature Measurements` section. This is app behaviour with very dense features, not a test defect.
- **Stale preview reuse.** `reuseExistingServer` reuses whatever is listening on port 4173 locally — stop any running preview before a verification run (see the note under [Running the Tests](#running-the-tests)).
