# Export and Measurement

> The side panel turns the current Terra Draw snapshot into counts, measurements and downloadable files — all in the browser, with no server round-trip.

The panel is rendered by [`home/index.tsx:189-218`](../src/routes/home/index.tsx) and toggles between two tabs, both fed from the same `features` snapshot.

## Info Tab

[`InfoTab.tsx`](../src/components/info-tab/InfoTab.tsx) is the inventory and measurement view.

### Guidance feature filtering

Terra Draw snapshots contain editing aids alongside real geometry. `isGuidanceFeature` (`InfoTab.tsx:10-21`) treats a feature as guidance when any of `selectionPoint`, `midPoint`, `closingPoint`, `snappingPoint`, `coordinatePoint` or `virtualPoint` is set. A "Hide guidance features" checkbox (`InfoTab.tsx:81-88`), on by default, excludes them from the table, badges and measurements; turning it off shows the raw snapshot.

### Counts and table

- Badges show totals for **All features**, **Polygons**, **Lines** and **Points** (`InfoTab.tsx:90-107`), classified by `geometry.type` (`InfoTab.tsx:42-60`).
- The table lists ID (first 8 characters), geometry type and `createdAt`/`updatedAt` timestamps formatted by `formatDateTime` (`InfoTab.tsx:108-151`).
- Clicking a row calls `onSelectFeature`; the route switches Terra Draw to select mode and highlights the feature on the map (`home/index.tsx:98-113`). Guidance rows are rendered as non-selectable (`InfoTab.tsx:120-132`).

### Measurements

For the selected feature (`InfoTab.tsx:152-177`):

| Geometry   | Measurement | Implementation                                                                    |
| ---------- | ----------- | --------------------------------------------------------------------------------- |
| Polygon    | Area        | Turf `area` in m², switched to km² at 1,000,000 m² (`InfoTab.tsx:8,62-74`)        |
| LineString | Length      | Turf `length` in km (`InfoTab.tsx:162-166`)                                       |
| Both       | Coordinates | Polygon outer-ring length, or LineString coordinate count (`InfoTab.tsx:168-175`) |

Turf's default units are used: square metres for `area`, kilometres for `length`. Both functions are re-exported through [`src/utils/geo.ts`](../src/utils/geo.ts) so components never import Turf directly.

## GeoJSON Tab

[`GeoJSONTab.tsx`](../src/components/geojson-tab/GeoJSONTab.tsx) is the raw view and export surface.

- The snapshot is wrapped in a `FeatureCollection` (`GeoJSONTab.tsx:13-19`) and stringified with 4-space indentation (`GeoJSONTab.tsx:23-25`), memoised on `features`.
- A read-only `<textarea>` displays the GeoJSON (`GeoJSONTab.tsx:42-44`).
- A copy button appears only when `navigator.clipboard` exists and writes the same string (`GeoJSONTab.tsx:35-37,45-51`).
- An export section offers a format select — **GeoJSON** or **FlatGeobuf** (`GeoJSONTab.tsx:54-68`) — and a single Download button dispatching on the selected format (`GeoJSONTab.tsx:31-33`).

Filenames are `terradraw_<fileDate()>.geojson` or `.fgb`, where `fileDate()` is a filesystem-safe timestamp (`utils/dates.ts:11-17`).

## Download Hooks

Both export paths follow the same pattern: create a `Blob`, turn it into an object URL, click a detached anchor with a `download` attribute, then revoke the URL.

- **JSON** — [`useDownloadJSON.ts`](../src/components/geojson-tab/useDownloadJSON.ts) stringifies the collection and downloads it as `text/plain` (`useDownloadJSON.ts:4-31`).
- **FlatGeobuf** — [`useDownloadFlatGeobuf.ts`](../src/components/geojson-tab/useDownloadFlatGeobuf.ts) dynamically imports FlatGeobuf's GeoJSON module (`useDownloadFlatGeobuf.ts:8`), serialises to a `Uint8Array` and downloads it as `octet/stream` (`useDownloadFlatGeobuf.ts:12-17`). The dynamic import keeps `flatgeobuf` (and its dependencies) out of the initial bundle; it is fetched only when someone actually exports FGB.

> [!NOTE]
> The FlatGeobuf import is a deep subpath (`flatgeobuf/lib/mjs/geojson`). It works with the pinned 3.x layout but couples the code to the package's internal structure — check it on a major upgrade.

## Everything Is Client-Side

There are no API calls, uploads or server-side rendering of features anywhere in this flow. Measurements run during render via `useMemo`, and downloads are created with in-browser Blob URLs, so feature data never leaves the visitor's machine.

Two small caveats:

- Clipboard writes require a secure context and permission; `localhost` counts as secure in development.
- The downloaded GeoJSON is exactly the current snapshot. It can include guidance features if they are present at the time — the guidance filter is an Info tab concern only. Use the Info tab's "Hide guidance features" toggle to check what you are about to export.
