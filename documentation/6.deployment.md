# Deployment

> GitHub Actions builds the static site and publishes it through the GitHub Pages Actions pipeline, served at [terradraw.io](https://terradraw.io).

## Build Output

`npm run build` runs `vite build` (`package.json:8`). Vite writes to `docs/` because [`vite.config.ts:7-9`](../vite.config.ts) sets `build.outDir: "docs"`, wiping and recreating it each time.

The result is a plain static bundle: `docs/index.html`, hashed JS/CSS/assets. Because prerendering is disabled, `index.html` contains an empty `#app` and the app renders client-side after hydration — see [Architecture](2.architecture.md).

> [!WARNING]
> `docs/` is **build output**, not documentation. It is gitignored ([`.gitignore:5`](../.gitignore)) and overwritten by every build. Developer docs live in `documentation/`.

## CI — `ci.yml`

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) runs on pushes to `main` and on pull requests (opened, synchronised, reopened, ready for review). All jobs run on `ubuntu-24.04` with Node `24.18.0` and `npm ci` (except `package-lock`, as below):

| Job             | Steps                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| `lint`          | `npm run lint`                                                                                                |
| `package-lock`  | `npm install --package-lock-only --no-audit --no-fund`, then `git diff --exit-code` to reject uncommitted lockfile changes |
| `typecheck`     | `npm run typecheck`                                                                                           |
| `build`         | `npx playwright install --with-deps chromium`, `npm run build`, `npm test`                                    |

The `package-lock` job is the reason to install with `npm ci` locally rather than letting `npm install` rewrite the lockfile. The `build` job exercises the real production build before running the full Playwright suite — smoke, drawing, export, theming, fixture and capture-guard meta-tests, the committed documentation captures and the twelve-capture responsivity matrix (see [Testing](5.testing.md)).

## Deploy — `deploy-pages.yml`

[`.github/workflows/deploy-pages.yml`](../.github/workflows/deploy-pages.yml) runs on pushes to `main` and on manual dispatch. It requests `contents: read`, `pages: write` and `id-token: write`, and uses a `pages` concurrency group with `cancel-in-progress: false`, so deployments queue rather than cancel each other.

The `build` job (`deploy-pages.yml:19-43`):

1. Checks out the repo and sets up Node `24.18.0` with npm caching (`deploy-pages.yml:22-29`).
2. Runs `npm ci` and `npm run build` (`deploy-pages.yml:31-35`).
3. Configures Pages with `actions/configure-pages@v6` and uploads the `docs/` build as a Pages artifact with `actions/upload-pages-artifact@v5` (`deploy-pages.yml:37-43`).

The `deploy` job (`deploy-pages.yml:45-54`) depends on `build`, runs in the `github-pages` environment and publishes the uploaded artifact with `actions/deploy-pages@v5`. There is no `gh-pages` branch push and no generated `CNAME`; the `terradraw.io` custom domain is served from the repository's Pages configuration. This workflow builds only; testing is the CI pipeline's responsibility.

> [!NOTE]
> Both workflows trigger on `main`, which is this repository's authoritative branch. Work on a branch or PR; merges to `main` are what build, test and deploy.

CI and deploy now pin the same Node patch (`24.18.0`). Local development only requires Node 24 (`README.md`).

## Runtime CDN Dependencies

The deployed site is not self-contained. At runtime it loads:

- Google Fonts (Open Sans) — `index.html:10-12`
- Leaflet CSS from unpkg — `index.html:13-14` (unused at runtime; see [Architecture](2.architecture.md))
- The Mapbox RTL text plugin from unpkg — [`setup-maplibre.ts:58-63`](../src/routes/home/setup-maplibre.ts)
- Basemap styles and tiles — keyless OpenFreeMap: `tiles.openfreemap.org/styles/positron` for light or `tiles.openfreemap.org/styles/dark` for dark, chosen from the OS preference; the same host serves both styles' vector tiles, glyphs and sprites — [`setup-maplibre.ts:65-66`](../src/routes/home/setup-maplibre.ts)
- The external TypeDoc site in the API tab iframe — [`api-docs/index.tsx:9`](../src/routes/api-docs/index.tsx), which itself renders dark when the page does

A CDN or network outage degrades the map (no style/tiles), text rendering and the API tab. There is no offline mode despite the leftover service worker and manifest stubs.
